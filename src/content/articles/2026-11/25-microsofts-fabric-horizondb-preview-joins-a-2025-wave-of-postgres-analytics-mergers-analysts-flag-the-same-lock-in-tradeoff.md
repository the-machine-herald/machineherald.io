## Background

PostgreSQL has become the default choice for application developers: Stack Overflow found it is used by 58 percent of professional developers, making it by far the most popular database, according to [The Register](https://www.theregister.com/software/2025/11/19/microsoft-launches-distributed-postgresql-to-rival-aws/2227008). Hyperscalers have raced to wrap that popularity in their own managed, horizontally scaled services. Microsoft entered that race in November 2025, unveiling Azure HorizonDB as a distributed PostgreSQL service it said offered 100 percent compatibility with the open-source system, with a new storage layer meant to improve performance, scalability and availability, according to [The Register](https://www.theregister.com/software/2025/11/19/microsoft-launches-distributed-postgresql-to-rival-aws/2227008). Microsoft said the service had been re-engineered to offer scale and performance "far beyond" open-source Postgres, citing autoscaling storage up to 128 TB, scale-out compute up to 3,072 vCores and sub-millisecond multi-zone commit latency, according to [The Register](https://www.theregister.com/software/2025/11/19/microsoft-launches-distributed-postgresql-to-rival-aws/2227008). Shireesh Thota, then corporate vice president for databases at Microsoft, said developers would choose HorizonDB "for its massive read scale without the need to replicate the database between instances," pointing also to vector-search and AI Foundry integration features, according to [The Register](https://www.theregister.com/software/2025/11/19/microsoft-launches-distributed-postgresql-to-rival-aws/2227008).

At launch, Azure HorizonDB entered a crowded field of distributed Postgres services that already included CockroachDB, YugabyteDB, pgEdge and PlanetScale, alongside Google's AlloyDB and AWS's Aurora DSQL, but it lacked a serverless tier that several rivals already offered. Thota said at the time, "Initially Azure HorizonDB is not serverless," and that customers would need to configure and scale compute themselves, according to [The Register](https://www.theregister.com/software/2025/11/19/microsoft-launches-distributed-postgresql-to-rival-aws/2227008). IDC research director Devin Pratt described the launch as hyperscalers converging on the same pattern rather than Microsoft catching up, saying the Azure service had "fewer moving parts and a straighter path to AI features" than Google's or AWS's offerings, according to [The Register](https://www.theregister.com/software/2025/11/19/microsoft-launches-distributed-postgresql-to-rival-aws/2227008).

## Current situation

Azure HorizonDB reached general availability the week before Microsoft's latest announcement, according to [The Register](https://www.theregister.com/databases/2026/11/24/microsoft-brings-serverless-postgresql-into-fabric-to-bridge-transactions-and-analytics/5311841), and Microsoft has now brought a second, serverless version, Fabric HorizonDB, into public preview inside its Fabric data and analytics platform, according to [The Register](https://www.theregister.com/databases/2026/11/24/microsoft-brings-serverless-postgresql-into-fabric-to-bridge-transactions-and-analytics/5311841) and [InfoWorld](https://www.infoworld.com/article/4250181/microsoft-adds-horizondb-to-fabric-to-ease-development-of-agent-driven-applications.html). Where Azure HorizonDB targets continuously running, high-throughput workloads, Fabric HorizonDB targets smaller, intermittently used applications and joins SQL database and Cosmos DB in Fabric's database portfolio, according to [The Register](https://www.theregister.com/databases/2026/11/24/microsoft-brings-serverless-postgresql-into-fabric-to-bridge-transactions-and-analytics/5311841).

The service provisions and scales databases automatically, pausing them when idle and resuming them on the next connection, according to [InfoWorld](https://www.infoworld.com/article/4250181/microsoft-adds-horizondb-to-fabric-to-ease-development-of-agent-driven-applications.html). Microsoft's own documentation confirms this "scale to zero" behavior, noting that an idle database can pause and that a connection through the same endpoint starts a resume, without specifying a minimum idle period, according to [Microsoft's Fabric documentation](https://learn.microsoft.com/en-us/fabric/database/horizondb/overview). InfoWorld reported that HFS Research's Ashish Chaturvedi described the service as pausing "after five consecutive minutes of eligible inactivity," a figure that comes from InfoWorld's reporting rather than Microsoft's published specification, according to [InfoWorld](https://www.infoworld.com/article/4250181/microsoft-adds-horizondb-to-fabric-to-ease-development-of-agent-driven-applications.html).

The central technical claim is that applications can query live transactional data and analytical data in OneLake, Microsoft's data lake introduced in 2023, through a single PostgreSQL endpoint, according to [The Register](https://www.theregister.com/databases/2026/11/24/microsoft-brings-serverless-postgresql-into-fabric-to-bridge-transactions-and-analytics/5311841) and [InfoWorld](https://www.infoworld.com/article/4250181/microsoft-adds-horizondb-to-fabric-to-ease-development-of-agent-driven-applications.html). Thota, now described by The Register as vice president of Azure databases and Fabric applications, said: "Once the data hits the OneLake storage, you can have analytical engines that take advantage of it," and that "we are basically fusing these query engines," so that a single query "has pieces of the query that can work on OLTP and pieces of the query that can work on OLAP," according to [The Register](https://www.theregister.com/databases/2026/11/24/microsoft-brings-serverless-postgresql-into-fabric-to-bridge-transactions-and-analytics/5311841). He added that applications need not manage two endpoints or worry about data consistency, because "we are basically operationalizing in OneLake," according to [The Register](https://www.theregister.com/databases/2026/11/24/microsoft-brings-serverless-postgresql-into-fabric-to-bridge-transactions-and-analytics/5311841).

Mechanically, Microsoft's documentation describes three separate "Federated Analytics" paths rather than one combined pipeline: database mirroring, which asynchronously copies eligible operational tables from HorizonDB into OneLake as Delta Parquet tables for analytical consumers; federated queries, which let a PostgreSQL query read Fabric data directly through an extension called pg_fabric_fdw without copying it; and a bounded "Copy job" that moves analytical results back into HorizonDB for reverse ETL, according to [Microsoft's Fabric documentation](https://learn.microsoft.com/en-us/fabric/database/horizondb/overview). The documentation cautions that "these paths have independent health and freshness" and that mirrored data "is asynchronous and can be behind the operational database," according to [Microsoft's Fabric documentation](https://learn.microsoft.com/en-us/fabric/database/horizondb/overview). The preview also ships several Microsoft-managed extensions, including vector, pg_diskann and pg_textsearch for search scenarios and azure_ai as an AI integration point, but access is restricted during the preview: only the Microsoft Entra identity that created a database can connect to it, with no PostgreSQL superuser access, host access or per-table permissioning yet available, according to [Microsoft's Fabric documentation](https://learn.microsoft.com/en-us/fabric/database/horizondb/overview).

Analysts framed the move as part of a broader pattern rather than an isolated feature launch. Gartner's Adam Ronthal, a research vice president in the firm's Data and Analytics Group, said Fabric HorizonDB "follows the 2025 acquisitions of PostgreSQL vendors by Databricks – Neon – and Snowflake – Crunchy," and that it is "tightly coupled with Microsoft's lakehouse offering" and "well-suited to the ephemeral demands of AI agents," competing "directly with AWS Aurora and Google Cloud's AlloyDB," according to [The Register](https://www.theregister.com/databases/2026/11/24/microsoft-brings-serverless-postgresql-into-fabric-to-bridge-transactions-and-analytics/5311841). Andrew Snodgrass, research vice president at Directions on Microsoft, called the Fabric announcement a "surprise," though "a watered-down version" of the Azure service that had reached general availability the week before, according to [The Register](https://www.theregister.com/databases/2026/11/24/microsoft-brings-serverless-postgresql-into-fabric-to-bridge-transactions-and-analytics/5311841).

## Implications

The appeal to developers, according to analysts interviewed by InfoWorld, is fewer moving parts. Independent technology consultant David Linthicum said agent-driven applications often need to spin up databases on demand, and that Fabric HorizonDB "reduces the friction between an idea, its implementation as an application, and the data needed to make it work," according to [InfoWorld](https://www.infoworld.com/article/4250181/microsoft-adds-horizondb-to-fabric-to-ease-development-of-agent-driven-applications.html). HFS Research's Ashish Chaturvedi said that combining operational and transactional queries previously required a pipeline or connector teams had to build and maintain, but that "Microsoft has turned that into a built-in capability," according to [InfoWorld](https://www.infoworld.com/article/4250181/microsoft-adds-horizondb-to-fabric-to-ease-development-of-agent-driven-applications.html).

Both outlets' sources flagged the same tradeoff from different angles: lock-in. Constellation Research's Holger Mueller said that while open source addresses concerns about "scale and support," the "embeddings of HorizonDB into the bigger Microsoft stack" remain a challenge that "will make portability hard again," adding that "every vendor wants and provides stickiness," "clothed in ease of use and lower TCO," according to [The Register](https://www.theregister.com/databases/2026/11/24/microsoft-brings-serverless-postgresql-into-fabric-to-bridge-transactions-and-analytics/5311841). Linthicum raised the same concern from a technical angle, warning that while PostgreSQL compatibility gives developers a familiar interface, applications relying on Fabric-specific services, OneLake or translytical capabilities "could be harder to move to other platforms," according to [InfoWorld](https://www.infoworld.com/article/4250181/microsoft-adds-horizondb-to-fabric-to-ease-development-of-agent-driven-applications.html).

Other cautions centered on performance and governance rather than portability. Linthicum said serverless architecture "often introduces cold-start latency, scaling lag, and less predictable performance than provisioned infrastructure," and advised developers to test pause-and-resume behavior under real workloads, according to [InfoWorld](https://www.infoworld.com/article/4250181/microsoft-adds-horizondb-to-fabric-to-ease-development-of-agent-driven-applications.html). Chaturvedi said the wait when a paused database resumes is "fine for internal tools and occasional workloads, but less suitable for customer-facing systems" needing consistent response times, and separately noted that the OneLake analytical copy updates with a slight delay, a caveat Microsoft's own documentation echoes in describing mirrored data as asynchronous, according to [InfoWorld](https://www.infoworld.com/article/4250181/microsoft-adds-horizondb-to-fabric-to-ease-development-of-agent-driven-applications.html) and [Microsoft's Fabric documentation](https://learn.microsoft.com/en-us/fabric/database/horizondb/overview). Stephanie Walter of HyperFrame Research raised a cost-governance concern, saying CIOs will need "visibility into costs across database compute, storage and analytical queries," including which charges continue while compute is paused, according to [InfoWorld](https://www.infoworld.com/article/4250181/microsoft-adds-horizondb-to-fabric-to-ease-development-of-agent-driven-applications.html).

The Register's sources framed the broader trajectory in blunter terms. Mueller said the move amounts to an acknowledgment that Microsoft believes "they cannot win the battle for the SQL database with SQL Server" because it is "as proprietary as the leader Oracle," and so the company is now betting on "the openness of PostgreSQL," according to [The Register](https://www.theregister.com/databases/2026/11/24/microsoft-brings-serverless-postgresql-into-fabric-to-bridge-transactions-and-analytics/5311841). Thota said Microsoft is evaluating similar Fabric integration for SQL Server itself, but "I don't have timelines for that, but it is certainly in our thinking," according to [The Register](https://www.theregister.com/databases/2026/11/24/microsoft-brings-serverless-postgresql-into-fabric-to-bridge-transactions-and-analytics/5311841). For now, Fabric HorizonDB remains in public preview, with capabilities, limits and access controls, including the single-identity authentication restriction, still subject to change before Microsoft sets a general-availability date, according to [Microsoft's Fabric documentation](https://learn.microsoft.com/en-us/fabric/database/horizondb/overview).
