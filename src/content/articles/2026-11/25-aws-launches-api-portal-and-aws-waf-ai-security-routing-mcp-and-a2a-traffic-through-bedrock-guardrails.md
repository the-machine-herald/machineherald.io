## Overview

Amazon Web Services has launched a new feature in Amazon API Gateway called API Portal, which finds API and AI endpoints across an AWS account or organization, alongside two new AWS WAF managed rule groups, API Security and AI Security, which screen traffic to those endpoints — including large language model (LLM) endpoints, Model Context Protocol (MCP) servers, and Agent2Agent (A2A) servers — for abuse. According to [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/waf-ai-endpoint-discovery-protection/), the capabilities let customers "discover language model (LLM), Model Context Protocol (MCP), and Agent2Agent (A2A) endpoints behind Amazon API Gateway, Application Load Balancers, and Amazon CloudFront across your AWS Organization and protect them using AWS WAF." All three capabilities are generally available as of November 23, 2026, according to the [AWS Security Blog](https://aws.amazon.com/blogs/security/introducing-api-and-ai-security-on-aws-from-discovery-to-protection/), which was published under the names of four AWS staffers: Gopinath Durairaj, Eitav Arditti, Gabe Sin, and Aykut Tuzunkan.

## What We Know

- **Discovery without instrumentation.** API Portal "recognizes the AI endpoints among the APIs it discovers automatically from traffic logs and service configuration records, with no agents to deploy or logs to forward," according to [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/waf-ai-endpoint-discovery-protection/). The AWS Security Blog post explains why this matters: "A new MCP server or LLM endpoint takes minutes to stand up. It can be placed behind a load balancer or a CloudFront distribution without ever passing through your API gateway, so it’s missing from the API registry and the security review." An unmanaged endpoint like that shows up in the inventory as a shadow API. AWS's own example: "An undocumented, public-facing MCP server appears as a shadow API," according to [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/waf-ai-endpoint-discovery-protection/). The Security Blog post adds that the same inventory also flags "zombie APIs," described as ones "which have no traffic and no configuration change for a set period," and "orphaned APIs, whose owning account was closed or removed from your organization."
- **Two separate managed rule groups.** API Security "covers three kinds of API abuse: broken object level authorization, authentication attacks such as tampered tokens and credential stuffing, and reconnaissance such as probing for undocumented routes," combining single-request rules with behavioral detections that "learn your traffic," according to the [AWS Security Blog](https://aws.amazon.com/blogs/security/introducing-api-and-ai-security-on-aws-from-discovery-to-protection/). The blog post names broken object level authorization, or BOLA, as "the first entry in the OWASP API Security Top 10." AI Security is the separate rule group for AI traffic: it "implements protocol recognition and compliance checks to block malformed MCP and A2A messages," according to [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/waf-ai-endpoint-discovery-protection/).
- **Protocol-version checks.** The AI Security rule group's first layer validates each MCP or A2A request against the protocol version it declares in its header. It "supports MCP versions 2025-06-18, 2025-11-25, and 2026-07-28, and A2A version 1.0," per the [AWS Security Blog](https://aws.amazon.com/blogs/security/introducing-api-and-ai-security-on-aws-from-discovery-to-protection/). These checks run in two tiers: a "Baseline" tier that blocks by default and covers violations that "let a request slip past routing or inspection," and a stricter tier that only counts malformed requests "usually" caused by an outdated client. As an example of what Baseline catches, AWS describes a request whose header declares a read-only `tools/list` call while the message body actually invokes a tool that reads a file — AWS WAF blocks it "because the header and the body disagree about the method."
- **Bedrock Guardrails does the content inspection.** When content inspection is turned on, the AI Security rule group "calls Amazon Bedrock Guardrails InvokeGuardrailsCheck API to detect prompt injection, jailbreak attempts, harmful content in requests, and sensitive information in responses," according to [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/waf-ai-endpoint-discovery-protection/). AWS WAF calls Guardrails using a customer-chosen service role rather than requiring customers to build their own guardrail, per the [Security Blog](https://aws.amazon.com/blogs/security/introducing-api-and-ai-security-on-aws-from-discovery-to-protection/), and by default it "blocks a high-severity prompt attack, on the request or the response," while lower-severity findings are only counted and labeled.
- **Availability and what's still missing.** API Portal is available in 32 AWS Regions, while the AI Security rule group's Bedrock Guardrails checks are available in a shorter, named list of regions: "US East (N. Virginia), US East (Ohio), US West (Oregon), Europe (London), Europe (Stockholm), Asia Pacific (Tokyo), and Asia Pacific (Sydney)," according to [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/waf-ai-endpoint-discovery-protection/). The Security Blog post also discloses a gap in the API Security rule group at launch: "Detection of data exfiltration and sensitive data exposure in responses for API Security is coming soon" — meaning that capability does not yet ship.
- **An early customer reaction.** The Security Blog post quotes one named API Portal user: "We can manage our API environment more effectively when we have a clear picture of what’s running across AWS. API Portal gives us that visibility without requiring teams to change how they deploy APIs or route traffic, helping us create a more complete view across the enterprise," said Mike Hasani, Senior Software Engineer, Principal Financial Group.

## What We Don't Know

Neither AWS publication discloses a dollar price for any of the three capabilities. AWS says only that "Each capability is priced by the service it runs in" — API Portal under Amazon API Gateway pricing, the two managed rule groups under AWS WAF pricing, and the Bedrock Guardrails content checks under Amazon Bedrock pricing, according to the [Security Blog](https://aws.amazon.com/blogs/security/introducing-api-and-ai-security-on-aws-from-discovery-to-protection/). AWS has not said how many customers have enabled API Portal or either rule group since launch, nor when the pending data-exfiltration detection for API Security will ship. As of publication, no AWS publication reviewed for this article names other cloud providers' comparable AI-endpoint security offerings or compares pricing or coverage against them.

## Why It Matters

The launch responds to a problem AWS frames as a new category of API caller. "APIs have always had two kinds of callers: other services and people who use an app. Now there’s a third: AI agents that act on a person’s behalf," the Security Blog post says, adding that an MCP or A2A endpoint "describes itself" to any agent that can reach it — "an MCP client asks the server for its tools with tools/list, and an A2A client reads the agent card that the server publishes" — without requiring documentation or passing through a reviewed gateway. By pairing discovery (API Portal) with protocol-aware blocking and Bedrock Guardrails content inspection in the same AWS WAF protection pack that already screens an organization's conventional web and API traffic, AWS is positioning the launch as infrastructure for securing the growing number of internal and public-facing AI agent endpoints that, by the company's own description, are easy to stand up and easy to miss during a security review.
