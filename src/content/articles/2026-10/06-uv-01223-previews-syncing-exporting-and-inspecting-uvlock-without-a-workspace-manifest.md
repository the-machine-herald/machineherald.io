## Overview

The Python package and project manager uv shipped version 0.12.23 on 2026-10-03, according to the [uv release page](https://github.com/astral-sh/uv/releases/tag/0.12.23). Its main addition is a preview feature, `frozen-lockfile`, that lets several `--frozen` commands operate directly on a `uv.lock` file without a workspace manifest being present.

## What Changed in 0.12.23

Per the [uv changelog](https://raw.githubusercontent.com/astral-sh/uv/main/CHANGELOG.md), four preview entries use `frozen-lockfile`:

- Syncing: "Sync from `uv.lock` without a workspace manifest using `uv sync --frozen`".
- Exporting: "Export from `uv.lock` without a workspace manifest using `uv export --frozen`".
- Dependency trees: "Inspect dependency trees from `uv.lock` without a workspace manifest using `uv tree --frozen`".
- Workspace metadata: "Inspect workspace metadata and optionally sync its environment from `uv.lock` without a workspace manifest using `uv workspace metadata --frozen`".

The changelog files these entries under its preview-features heading, meaning the behavior is experimental. It does not explain the intended use cases, so how teams might apply the feature, for example in build or deployment steps that carry a lockfile but not the project manifests, is not described by the project.

Two bug fixes landed in the same release, per the [changelog](https://raw.githubusercontent.com/astral-sh/uv/main/CHANGELOG.md). One entry reads "Reject alternate sources for workspace members across conflicting dependency selections, avoiding lockfiles that cannot be installed". The other reads "Allow x86-64 Python interpreters running under emulation on Windows ARM64 to install compatible `win_amd64` wheels instead of building from source". The release also adds CPython 3.15.0rc3, according to the [release page](https://github.com/astral-sh/uv/releases/tag/0.12.23).

## A Run of Lockfile Changes

The release follows several others in the 0.12.2x series that touched what uv writes into `uv.lock`, as listed in the [changelog](https://raw.githubusercontent.com/astral-sh/uv/main/CHANGELOG.md):

- **0.12.20:** "Reuse lockfiles when dependency declarations are semantically equivalent", plus a `lockfile-normalization` preview feature that writes normalized requirement declarations.
- **0.12.21:** "Omit empty `[manifest]` tables from lockfiles that contain only manifest subtables", and a `resolution-inputs` preview feature to omit redundant runtime constraints from `uv.lock`.
- **0.12.22:** the lockfile now records workspace-member default groups and workspace-member dependency-group Python requirements, with the same two records added for non-project workspace roots. The same release also fixed frozen sync so that it uses "each selected workspace member's recorded default groups".

The 0.12.22 entries on recorded default groups bear on the new feature: a frozen sync that has no manifest to read can only rely on what the lockfile itself records. The changelog does not state that this was the motivation, and that link is an inference from the sequence of entries rather than a statement by the project.

## Other Items in 0.12.22

The [changelog](https://raw.githubusercontent.com/astral-sh/uv/main/CHANGELOG.md) also lists a new `UV_PYTHON_ARCH` setting, described as a way to "select an interpreter architecture independently of its Python version". The same release adds CPython 3.10.22, 3.11.17, 3.12.15, 3.13.16 and 3.14.8.

## What We Don't Know

- Whether and when `frozen-lockfile` will graduate from preview to stable behavior; the changelog gives no timeline.
- Whether the lockfile-recording changes in 0.12.22 were made specifically to support manifest-free frozen commands.
- How the preview commands behave when a lockfile was generated by an older uv version, which the cited release notes do not address.
